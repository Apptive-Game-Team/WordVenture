## Execution Notes

- `docker compose up -d`는 컨테이너 생성·시작에 성공했다. 초기화 완료 전에 새 WSL 실행이 반복적으로 `Wsl/Service/0x8007274c` 오류를 반환했다.
- 셸을 거치지 않는 Docker 로그 조회와 `/bin/echo`도 응답 지연을 보여 WSL 자체 연결 장애로 판단했다. 다른 작업 중단을 피하기 위해 승인 없이 Ubuntu를 종료하지 않았다.
- 승인된 평원 v2의 원본·요청·메타데이터는 새 묶음에 복사했다. 신규 9곡의 완료 파일은 아직 확인되지 않았다.
- 생성기는 서버 준비를 최대 10분 기다린다. WSL 복구 후 기존 프로세스와 파일을 확인해 중복 생성 없이 재개한다.
- 사용자가 Ubuntu 재시작을 승인해 `wsl --terminate Ubuntu` 후 Compose를 다시 시작했다. WSL 명령이 정상 응답한다.
- 종료 원인 진단: Windows RAM 약 31.5GiB 중 여유 약 1.5GiB, 커밋 여유 약 5.4GiB. WSL 제한은 12GB RAM·8GB swap, GPU VRAM은 6GB다. 메모리 압박이 유력하지만 OOMKilled=false이며 강제 종료 원인은 확정되지 않았다. 컨테이너 restart policy는 no다.
- 추가 증거: 현재 커널 journal에 2026-10-16 14:10:41~14:11:32 KST부터 ACE Step 컨테이너 `2ac383e313a9...`의 `cuda-EvtHandlr: page allocation failure: order:4`가 반복된다. Docker inspect의 컨테이너 ID와 일치하며, 승인된 Ubuntu 종료(14:18)보다 앞선 기록이다. 14:18에는 같은 컨테이너의 Python에서도 실패가 기록됐다. WSL 메모리 할당 실패는 확인됐으나 OOM killer에 의한 프로세스 종료나 과거의 모든 꺼짐 원인을 확정하는 증거는 아니다. 메모리 압박/연속 메모리 확보 실패와 연관된 장애로 판단한다.
